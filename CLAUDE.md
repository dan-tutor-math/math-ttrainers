# Платформа «Тренажёры» Mathh — правила для Claude Code

Этот файл читается в начале каждой сессии. Держать его коротким.

## Проект

- Репозиторий dan-tutor-math/math-ttrainers (эта папка), сайт https://dan-tutor-math.github.io/math-ttrainers/
- Сборки нет: статические файлы, публикация — пуш в main
- База и realtime: Supabase, проект nctwdjyxlwnsbdkmisje
- Общие модули: session-share.js (совместные сессии), trainer-board.js (доска), trainer-multi.js (несколько заданий на экране), basket-core.js (подборка), lesson-history.js. Приложение досок: boards.html, boards-core.js, boards-cloud.js
- Вне репозитория: ../fipi-pilot (выгрузка и сверка банка ФИПИ), ../claude-notes/*.md (заметки по банку ФИПИ, по предметам). Открывать только когда задача про них

## HANDOFF.md — НЕ ЧИТАТЬ ЦЕЛИКОМ

- HANDOFF.md весит ~660 КБ (больше 150 тысяч токенов). Целиком его не открывать НИКОГДА
- Сначала оглавление: grep -n '^## ' HANDOFF.md. Разделы: 2 «Как работать», 3 «Карта файлов», 4 «Тренажёры», 5 «Совместная сессия», 6–7 «Доски», 8 «Грабли», 9 «Тесты», 12 «С чего начать»
- Потом читать только нужный кусок (Read с offset/limit) или grep по имени файла / функции
- Новое в HANDOFF.md дописывать коротко, в конец нужного раздела

## Экономия токенов — обязательно

- НЕ запускать субагентов (Agent / Task) и параллельные задачи, если я прямо не попросил. Делать всё самому, последовательно
- НЕ делать широких проверок «всех тренажёров», «всех типов», «всего репозитория», если я не попросил аудит. Работать только с файлами, которые касаются задачи
- Большие файлы (банки *-fipi.js, *-bank.js, HANDOFF.md) не читать целиком: grep, потом нужный кусок
- Скриншоты смотреть только когда тест упал или задача про вёрстку. Тесты playwright проверяют DOM и пишут результат текстом
- Прогонять только тесты, которых касается правка, не весь набор test_prompt*.py
- Если задача большая (больше 5–6 файлов или много страниц) — сначала коротко написать план и дождаться «да»
- Не пересказывать мне прочитанный код и не дублировать в ответе то, что видно в диффе

## Как работаем

- Никогда не коммитить и не пушить без моего явного разрешения на конкретную правку
- «Пуш», «пушим», «коммитим и пушим» — это разрешение: закоммитить и выполнить git push origin main. В ответ одна строка: хеш и «запушено». Если push не прошёл — ТОЛЬКО точный текст команды для пуша
- Сообщение коммита заканчивать строкой: Co-Authored-By: Claude <noreply@anthropic.com>
- git add — только поимённо. Никогда git add -A и git add . : в папке лежат незакоммиченные черновики вида boards-1.html, index-1.html
- git status и git log запускать с GIT_OPTIONAL_LOCKS=0. Залипшие .git/index.lock или .git/HEAD.lock отодвигать через mv в .git/_stale
- До коммита показать список изменённых файлов на проверку
- Каждую правку покрывать тестом на playwright (test_prompt*.py рядом с кодом) и прогонять его до того, как сказать «готово»
- Секретный ключ Supabase (service_role) не запрашивать и никуда не писать. В клиенте только публичный anon-ключ
- Не вводить пароли и не удалять аккаунты
- Правку, задевающую совместный режим (realtime), я перепроверяю на сайте руками — в конце напоминать об этом
- Любой тренажёр, любой предмет, и новые тоже: на экране задания всегда есть «◀ Предыдущий тип / Следующий тип ▶». Если внутри типа есть свой список заданий (банк ФИПИ и т. п.), «◀ Предыдущее / Следующее задание ▶» ставим рядом, а не вместо (HANDOFF, раздел 4, «кнопки типов»)
- В конце крупной правки: в HANDOFF.md — раздел 8 «Грабли», если наступили на новую, и строка в разделе 11 (история промптов)

## Как писать

- Комментарии в коде по-русски, объясняют ПОЧЕМУ так сделано, а не что делает строка
- Математические примеры вертикально, по одному в строке. Обыкновенные дроби — числитель над знаменателем, не через слэш
- Списки правок плоским текстом простыми тире, без вложенной нумерации
- Отвечать коротко, по-русски
